# Real Project Workflow - ACE Enterprise

**Status:** ✅ Complete
**Created:** 2025-11-30
**Milestone:** Phase 1 - Foundation

---

## Overview

ACE Enterprise now works with **real projects** instead of /tmp demos. You can initialize ACE in any Python project and build features directly in your codebase with full git integration.

---

## Quick Start

```bash
# 1. Go to your project
cd ~/my_project

# 2. Initialize ACE
python /path/to/ace_cli.py init --domain healthcare

# 3. Create a Gherkin feature
cat > features/auth.feature <<EOF
Feature: User Authentication
  Scenario: User login
    Given a user exists
    When they login
    Then access granted
EOF

# 4. Build it!
python /path/to/ace_cli.py build-feature features/auth.feature

# Generated in YOUR project:
# - src/auth.py
# - tests/test_auth.py
# - .ace/decisions/2025-11-30-auth.md
```

## Components

### 1. Project Detector (`src/project/detector.py`)

**Automatically detects:**
- Project root (setup.py, pyproject.toml, .git)
- Project name
- Source directory (src/, package name, or root)
- Test directory (tests/ or test/)
- Project type (package, application, script)
- Package manager (poetry, pip, conda)
- Python version

**Usage:**
```python
from src.project import ProjectDetector

detector = ProjectDetector()
project_info = detector.detect()

print(f"Project: {project_info.name}")
print(f"Source: {project_info.src_dir}")
print(f"Tests: {project_info.test_dir}")
```

### 2. Project Configuration (`src/project/config.py`)

**Creates `.ace/config.yml`:**
```yaml
project_name: my_app
project_domain: healthcare
test_framework: pytest
code_style: pep8
type_hints: true
docstrings: true
tdd_cycles: 3
use_central_knowledge: true
playbooks:
  - global
  - healthcare
```

**Project Structure:**
```
my_project/
├── .ace/
│   ├── config.yml       # ACE configuration
│   ├── decisions/       # Architectural Decision Records
│   │   └── 2025-11-30-feature-name.md
│   └── README.md        # ACE documentation
├── src/
│   └── feature.py       # Generated implementation
├── tests/
│   └── test_feature.py  # Generated tests
└── features/
    └── feature.feature  # Gherkin scenarios
```

### 3. CLI Interface (`ace_cli.py`)

**Commands:**

**`ace init`** - Initialize ACE in current project
```bash
python ace_cli.py init --domain healthcare

Creates:
- .ace/config.yml
- .ace/decisions/
- .ace/README.md
- tests/ (if doesn't exist)
```

**`ace build-feature <file>`** - Build feature from Gherkin
```bash
python ace_cli.py build-feature features/auth.feature

Generates:
- Implementation in src/
- Tests in tests/
- ADR in .ace/decisions/
```

**`ace status`** - Show project status
```bash
python ace_cli.py status

Shows:
- Project info
- ACE configuration
- Decision count
- Setup status
```

## Example Workflow

### Scenario: Add Authentication to Web App

```bash
# 1. Clone your project
cd ~/projects/my_web_app

# 2. Initialize ACE
python /path/to/ace_cli.py init --domain web_application

# Output:
# ✅ ACE initialized successfully!
# 📝 Configuration saved to: .ace/config.yml
#    Project: my_web_app
#    Domain: web_application
#    Test framework: pytest
#    Central knowledge: Enabled

# 3. Write Gherkin scenarios
mkdir -p requirements
cat > requirements/auth.feature <<'EOF'
Feature: User Authentication
  As a system admin
  I want users to authenticate
  So that only authorized users access the system

  Scenario: User with valid credentials can login
    Given a user with email "test@example.com"
    And a password "secure123"
    When they attempt to login
    Then access should be granted
    And a session token should be created

  Scenario: User with invalid credentials is denied
    Given a user with email "test@example.com"
    And a wrong password
    When they attempt to login
    Then access should be denied
    And an error message should be shown
EOF

# 4. Build feature (generates in YOUR project!)
python /path/to/ace_cli.py build-feature requirements/auth.feature

# Output:
# 🏗️ Building feature from: auth.feature
# 📁 Project: my_web_app
#    Source: /home/user/projects/my_web_app/src
#    Tests: /home/user/projects/my_web_app/tests
# ⚙️ Initializing ACE components...
# ✅ Components initialized
# 🔨 Starting Gherkin-driven TDD...
# (TDD cycles run...)
# ✅ Feature built successfully!
# 📝 Generating decision record...
#    Saved ADR: 2025-11-30-auth.md
# 📂 Generated files:
#    Source: /home/user/projects/my_web_app/src
#    Tests: /home/user/projects/my_web_app/tests
#    Decisions: /home/user/projects/my_web_app/.ace/decisions

# 5. Review generated code
cat src/auth.py
cat tests/test_auth.py
cat .ace/decisions/2025-11-30-auth.md

# 6. Run tests
pytest tests/test_auth.py -v

# 7. Review changes
git status
git diff

# 8. Commit
git add src/auth.py tests/test_auth.py .ace/
git commit -m "Add user authentication feature

- Implemented login with email/password
- Added session token generation
- Full test coverage from Gherkin scenarios
- Documented in ADR: .ace/decisions/2025-11-30-auth.md

Generated with ACE Enterprise"

git push
```

## Configuration Options

### `.ace/config.yml` Schema

```yaml
# Project metadata
project_name: string          # Auto-detected
project_domain: string | null # e.g., "healthcare", "fintech"
project_tags: list[string]    # Custom tags

# Knowledge
use_central_knowledge: bool   # Use ~/.ace/knowledge/
central_knowledge_path: string | null
playbooks: list[string]       # ["global", "healthcare"]
local_playbook: string | null # Project-specific

# Code generation
test_framework: string        # "pytest", "unittest", "nose"
code_style: string           # "pep8", "google", "numpy"
type_hints: bool
docstrings: bool

# TDD
tdd_cycles: int              # Max cycles (default: 3)
auto_fix: bool               # Auto-fix simple issues

# Provenance
contributors: list[string]    # ["dev@company.com"]
ai_models: list[dict]        # [{"provider": "...", "model": "..."}]

# Git
auto_stage: bool             # Auto-stage (default: false)
auto_commit: bool            # Auto-commit (default: false)
```
