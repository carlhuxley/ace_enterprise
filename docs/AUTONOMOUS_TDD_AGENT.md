# Autonomous Incremental TDD Agent

**Status**: 📋 DESIGN PHASE
**Date**: 2025-10-28
**Priority**: HIGH - Next Major Feature

---

## Vision

**A fully autonomous TDD agent that:**
1. Takes high-level feature requirements from humans
2. Writes tests incrementally (one at a time)
3. Implements minimal code to pass each test
4. Refactors when needed
5. Learns patterns via ensemble ACE
6. Returns complete, tested, refactored features
7. **No human in the loop during build process**

---

## The Problem We're Solving

**Current State:**
- Developers write tests manually
- Developers implement code manually
- ACE only learns from failures (reactive)
- Human bottleneck at every step

**Desired State:**
- Developer provides requirement: "Build user authentication"
- ACE autonomously writes tests + code using TDD
- ACE learns patterns during the build process
- Developer reviews finished feature
- **10x faster development with learned quality patterns**

```bash
git add models/user.py tests/test_user.py

```

### ACE's Autonomous TDD Loop

```
1. PLAN
   - Break requirement into incremental tests
   - Use ensemble to propose test sequence
   - Start with simplest, build up complexity

2. For each increment:

   a) WRITE TEST (RED Phase)
      - Generate next test using playbook patterns
      - Validate test quality (Test Review Agent)
      - Run test → should FAIL

   b) WRITE CODE (GREEN Phase)
      - Generate minimal code to pass test
      - Run test → should PASS
      - Iterate if needed (max 3 attempts)

   c) REFACTOR (REFACTOR Phase)
      - Analyze code for improvements
      - Refactor if needed
      - Run tests → must still PASS

   d) LEARN (LEARN Phase)
      - Ensemble proposes patterns learned
      - Voting on pattern quality
      - Deliberation for contested patterns
      - Update playbook

3. COMPLETE
   - All increments done
   - All tests passing
   - Code refactored
   - Return to developer
```

### 2. Increment Planner

**Purpose**: Break high-level requirements into incremental test steps

**Approach**: Ensemble-based planning
- Multiple models propose test sequences
- Vote on best sequence
- Deliberate on contested sequences

**Example:**

```
Requirement: "User registration with email validation"

Model A proposes:
1. test_user_can_be_created
2. test_user_requires_email
3. test_email_is_validated
4. test_password_is_hashed
5. test_user_can_authenticate

Model B proposes:
1. test_create_empty_user
2. test_add_email_to_user
3. test_validate_email_format
4. test_set_password
5. test_verify_password

Model C proposes:
1. test_user_initialization
2. test_email_validation
3. test_password_hashing
4. test_authentication

Ensemble votes → Selects best plan (or merges plans)
```

### 4. Minimal Code Generator

**Purpose**: Generate simplest code to pass test (TDD principle)

**Prompt Strategy:**

```python
prompt = f"""
Write the MINIMAL code to make this test pass:

{test_code}

Guidelines:
- Write the simplest thing that works
- Don't add features not tested yet
- Follow playbook patterns:
{playbook_patterns}

Return ONLY the code needed, nothing extra.
"""
```

**Example:**

```python
# Test
def test_user_can_be_created():
    user = User()
    assert user is not None

# Minimal code (TDD)
class User:
    pass  # Simplest thing that works!

# NOT this (over-engineering):
class User:
    def __init__(self, email: str, password: str):  # Not tested yet!
        self.email = email
        self.password = password
```

### 5. Refactoring Engine

**Purpose**: Improve code quality while keeping tests green

**Triggers:**
- Code duplication detected
- Long methods (>20 lines)
- Complex conditionals
- Magic numbers
- Playbook suggests refactoring pattern

**Process:**

```python
def _refactor_code():
    # 1. Identify refactoring opportunities
    issues = self._analyze_code_quality()

    if not issues:
        return  # Code is clean

    # 2. Apply refactoring
    for issue in issues:
        refactored_code = self._apply_refactoring(issue)

        # 3. Verify tests still pass
        result = self._run_tests()

        if result.passed:
            self.code = refactored_code  # Accept refactoring
        else:
            # Rollback refactoring, tests failed
            pass
```

**Example Refactoring:**

```python
# Before (after GREEN phase)
def create_user(email, password):
    if not re.match(r'^[\w\.-]+@[\w\.-]+\.\w+$', email):
        raise ValueError("Invalid email")
    if len(password) < 8:
        raise ValueError("Password too short")
    # ... more validation

# After refactoring
def create_user(email, password):
    validate_email(email)
    validate_password(password)
    # ... rest

    if not re.match(r'^[\w\.-]+@[\w\.-]+\.\w+$', email):
        raise ValueError("Invalid email")

def validate_password(password):
    if len(password) < 8:
        raise ValueError("Password too short")
```

### 6. Ensemble Learning Integration

**Purpose**: Learn patterns from each TDD cycle

**What Gets Learned:**

1. **Test Patterns**
   - "Start with test for object creation"
   - "Test edge cases: empty, null, invalid"
   - "Use pytest fixtures for setup"

2. **Implementation Patterns**
   - "Use bcrypt for password hashing"
   - "Validate email with email-validator library"
   - "Store UTC timestamps, not local time"

3. **Refactoring Patterns**
   - "Extract validation into separate functions"
   - "Use dataclasses for simple models"
   - "Prefer composition over inheritance"

**Learning Process:**

```python
# After each TDD cycle
task = TaskInput(
    query=f"Implement {test_name}",
    context={"test": test_code, "code": impl_code}
)

feedback = EnvironmentFeedback(
    result="PASSED",  # Test passed

    test_report=test_result.details

# Ensemble proposes patterns
result = self.ensemble_learner.learn_from_task(task, feedback)

# Voting on patterns:
# - Model A: "Use bcrypt for passwords" (approve: 3/3)
# - Model B: "Store passwords as plain text" (approve: 0/3) ❌

# Only high-quality patterns added to playbook
```

## Technical Challenges

### Challenge 1: Test Sequence Planning

**Problem**: How to break "user authentication" into incremental tests?

**Solution**: Ensemble-based planning
- Multiple models propose sequences
- Vote on best sequence
- Deliberate on contested sequences
- Adaptive: adjust plan based on results

### Challenge 2: Minimal Code Generation

**Problem**: LLMs tend to over-engineer (add untested features)

**Solution**: Strict prompting + validation
- Emphasize "minimal" in prompt
- Show only current test (hide future tests)
- Validate: only code needed for current test
- Reject if adds untested features

### Challenge 3: Refactoring Without Breaking Tests

**Problem**: Refactoring might break tests accidentally

**Solution**: Test-driven refactoring
- Run tests before refactoring
- Apply refactoring
- Run tests after refactoring
- If tests fail, rollback refactoring
- Learn from successful refactorings

### Challenge 4: Infinite Loops

**Problem**: ACE might get stuck (test always fails)

**Solution**: Multiple safeguards
- Max iterations limit (default: 20)
- Max attempts per test (default: 3)
- Progress detection (must pass more tests each cycle)
- Fallback: ask human for help

### Challenge 5: Playbook Pollution

**Problem**: Learning bad patterns from failures

**Solution**: Ensemble quality control
- Multiple models vote on patterns
- Deliberation for contested patterns
- Track pattern helpfulness
- Prune harmful patterns

## Metrics & Evaluation

### Build Quality Metrics

1. **Test Coverage**: % of code covered by tests
2. **Test Pass Rate**: % of tests passing
3. **Code Quality Score**: Linting, complexity, style
4. **Refactoring Count**: Number of refactoring cycles
5. **Build Time**: Minutes from start to completion

### Learning Metrics

1. **Patterns Learned**: New bullets per build
2. **Pattern Quality**: Approval rate in ensemble
3. **Deliberation Rate**: % of patterns that needed debate
4. **Playbook Growth**: Bullets over time
5. **Reuse Rate**: % of patterns used in future builds

### Efficiency Metrics

1. **First-Time Pass Rate**: % of tests passing on first try
2. **Iteration Count**: Avg cycles per feature
3. **Code Generation Efficiency**: Lines of code per minute
4. **Human Time Saved**: Hours saved vs manual development
